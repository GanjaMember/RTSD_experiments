# Исследование и оценка методов для задачи детекции дорожных знаков

## Обзор
Проект посвящён исследованию и сравнению методов детекции дорожных знаков на реальном датасете. Цель — оценить поведение разных архитектур и конфигураций в условиях небольшого количества данных и большого числа классов, а также выявить узкие места в обучении и предобработке для дальнейших улучшений.

## Мотивация
Детекция дорожных знаков — важная компонентa систем помощи водителю и беспилотных транспортных средств. Для повышения надёжности таких систем требуется понимание того, какие архитектуры и приёмы предобработки лучше работают на маломасштабных и несбалансированных наборах данных с преимущественно мелкими объектами.

## Данные
Для экспериментов использован датасет **RTSD-small (Russian Traffic Sign Detection)**:
- 2391 изображение (формат COCO);
- 155 классов, сильный дисбаланс классов;
- разрешения изображений: от 1280×720 до 1920×1080;
- изображения масштабирую до 640×640 для обучения;
- средний размер боксов после предобработки: ~18.1×30.4 пикселей; много боксов <16×16 пикселей.

Самого лучшего результата на RTSD добилась команда из Антона Конюшина, Бориса Фаизова и Влада Шакуры с их моделью PVANet - 86.16% mAP

## Задачи
- Сравнить несколько архитектур детекции (кастомные реализации и готовые модели);
- Оценить влияние выбора backbone, предобработки и гиперпараметров на mAP;
- Найти и устранить основные ошибки обучения и предобработки.

## Используемые модели и инструменты
- Кастомная реализация, близкая к YOLOX (PyTorch);
- Кастомный Faster R-CNN (ResNet-18, PyTorch);
- SSD и RetinaNet (реализация — mmdetection);
- mmdetection для серий экспериментов и получения бенчмарков;
- эксперименты с backbone: EfficientNet (разные версии).
- эксперименты с гиперпараметрами.

## Эксперименты и ключевые этапы
### Предобработка и подготовка
- Приведение аннотаций к COCO, масштабирование изображений к 640×640.
- Анализ распределения размеров боксов и подсчёт средних размеров якорей.

### Эксперименты с кастомными моделями
- модификация FPN (добавление уровней), расчёт средних размеров якорей;
- наблюдались проблемы с обучением: падение training loss при нулевом mAP и появление NaN;
- причина частично выявлена: некорректные размеры якорей (после `decode_boxes` получались отрицательные ширины/высоты). Добавлены ограничения в `decode_boxes` для защиты от некорректных значений;
- после доработок архитектуры удалось добиться непустого mAP (раньше — 0%).

### Переход к проверенным конфигурациям (mmdetection)
- интеграция конфигураций из mmdetection и запуск SSD/RetinaNet;
- лучшие результаты по mAP получены с использованием mmdetection; однако абсолютные значения mAP оставались низкими.

## Результаты
- Наилучший достигнутый результат на RTSD в рамках этого проекта: mAP ≈ 0.082 — 0.09 (в зависимости от конфигурации и аугментаций);
- Использование EfficientNet-b2 в качестве backbone показало лучшие результаты среди протестированных версий EfficientNet;
- Модель достигает плато качества очень быстро (уже за 2 эпохи в ряде конфигураций);
- Попытки улучшить результат изменением размеров входа (640→1280), изменением `weight_box` и числа эпох не дали существенного прироста в рамках доступных ресурсов;
- При ограничении датасета одним классом наблюдалась переобучаемость на тренировочном сете, но некорректное позиционирование боксов — знак о проблемах в loss-функции/оценке/аннотациях.

## Анализ причин низкого качества
- После завершения проекта я смог выяснить причину низкого качества: она заключается в слабой архитектуре, выбранной для сложной задачи. Удалось это выяснить в ходе запуска EfficientNet-b2 с правильно настроенными слоями на сильно упрощенном датасете, для тестирования я брал всего два класса вместо всех 155 классов.

## Выводы и дальнейшие направления
- Для повышения качества рекомендуется:
  - использовать предобработку, ориентированную на мелкие объекты (тензорные пайплайны, специальные аугментации, увеличение разрешения с учётом ресурсов);
  - пересмотреть стратегию аннотаций / объединение редко встречающихся классов;
  - попробовать архитектуры и модули, специально приспособленные для детекции мелких объектов (feature pyramid enhancements, attention-модули, суперрезолюция на уровне праймила);
  - провести более глубокую отладку и валидацию pipeline (контроль аннотаций, sanity-check для якорей и декодирования боксов).
- При ограниченных ресурсах целесообразно протестировать задачу на более простом/малом количестве классов для оценки «потолка» выбранной архитектуры.
- Если модель не обучается, то скорее всего задача слишком сложная, и архитектура просто-напросто не справляется с ней.
